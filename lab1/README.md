# Лабораторная работа 1. Основы ООП: разработка класса

Язык: C++17. Реализованы два варианта задания:

* **1.2 Англо-русский словарь** — класс `Dictionary` на двоичном дереве поиска;
* **1.5.2 Пятнашки** — класс `Fifteen`.

## Структура проекта

| Папка / файл | Что внутри |
|---|---|
| `include/Dictionary.h`, `src/Dictionary.cpp` | класс словаря (объявление и реализация отдельно) |
| `include/Fifteen.h`, `src/Fifteen.cpp` | класс пятнашек |
| `app/` | консольные программы с меню (`dictionary_app`, `fifteen_app`); классы о них ничего не знают |
| `tests/` | модульные тесты на doctest (`doctest.h` лежит в проекте, скачивать ничего не нужно) |
| `data/` | примеры файлов: `words.txt` (словарь), `fifteen_sample.txt` (поле) |
| `CMakeLists.txt`, `build.bat` | сборка |
| `Doxyfile` | настройки Doxygen |

## Сборка и запуск на Windows

Нужны **CMake** и компилятор: Visual Studio / Build Tools (открывайте «Developer Command Prompt») или MinGW (g++).

```bat
build.bat
```

Скрипт собирает проект и запускает тесты. Готовые программы лежат в `build\bin\`. Запускать удобно из папки `lab1`,
чтобы работали пути вида `data\words.txt`:

```bat
build\bin\dictionary_app.exe
build\bin\fifteen_app.exe
```

Без CMake, только с MinGW (из папки `lab1`):

```bat
g++ -std=c++17 -Iinclude app/dictionary_main.cpp app/ConsoleUtils.cpp src/Dictionary.cpp -o dictionary_app.exe
g++ -std=c++17 -Iinclude app/fifteen_main.cpp app/ConsoleUtils.cpp src/Fifteen.cpp -o fifteen_app.exe
g++ -std=c++17 -Iinclude -Itests tests/test_main.cpp tests/test_dictionary.cpp tests/test_fifteen.cpp src/Dictionary.cpp src/Fifteen.cpp -o lab1_tests.exe
```

Русские буквы: программы сами включают кодировку UTF-8 в консоли. Если вместо букв «кракозябры», запустите программу
в Windows Terminal или выполните `chcp 65001`. Файлы словаря должны быть в UTF-8.

## Тесты и покрытие

```bat
ctest --test-dir build -C Release --output-on-failure
```

Покрытие считается по коду классов (`src/`), консольное меню в него не входит. Измеренный результат с gcc + gcovr:
**99% строк** (требуется более 90%).

* MinGW / Linux: `cmake -S . -B build -DENABLE_COVERAGE=ON`, затем сборка, тесты и
  `gcovr -r . --object-directory build --filter src/ --print-summary` (`pip install gcovr`).
* Visual Studio: утилита OpenCppCoverage, например
  `OpenCppCoverage --sources src -- build\bin\lab1_tests.exe`.

## Форматы файлов

Словарь — по одной строке на слово, перевод отделяется точкой с запятой:

```
cat;кошка
dog;собака
```

Пятнашки — сначала размер поля, затем числа по строкам (0 — пустая клетка):

```
3
1 2 3
4 5 6
7 0 8
```

## Как требования задания реализованы

| Требование | Где |
|---|---|
| Инкапсуляция | данные в `private`, доступ только через методы |
| Интерфейс отделён от реализации | `.h` и `.cpp` в разных папках |
| UI отделён от классов | классы в библиотеке `lab1_core`, меню в `app/` |
| Конструктор копирования, `=` | `Dictionary` — глубокое копирование дерева, `=` через copy-and-swap; `Fifteen` — `= default` (внутри `std::vector`) |
| Освобождение ресурсов | деструктор `Dictionary` удаляет все узлы; в `Fifteen` память освобождает `std::vector` |
| `==`, `!=` | оба класса |
| Чтение и запись в поток | `operator<<` и `operator>>` в обоих классах |
| Словарь: `+=` | для `std::string` и для C-строк (`std::make_pair("cat", "кошка")`) |
| Словарь: `-=`, `[]`, количество слов, загрузка | `-=`, `operator[]` (поиск и замена перевода), `size()`, `loadFromFile()` |
| Пятнашки: случайная расстановка | `randomize()` — случайные допустимые ходы из собранного состояния, поэтому собрать можно всегда |
| Пятнашки: перестановка, `[]`, проверка | `moveTile()`, `operator[]`, `isSolved()` |

## Что полезно знать к защите

* **Удаление из дерева**: три случая — лист, один потомок, два потомка. В последнем узел заменяется
  минимальным элементом правого поддерева, затем этот элемент удаляется.
* **copy-and-swap**: оператор `=` создаёт копию и меняет её местами с `*this`; самоприсваивание безопасно,
  а если копирование упадёт, исходный объект не пострадает.
* **Почему расстановку можно собрать**: каждый ход меняет чётность перестановки предсказуемым образом, поэтому
  из собранного состояния нельзя случайными ходами получить несобираемое. Метод `isSolvable()` проверяет это
  по числу инверсий (для чётного размера учитывается строка пустой клетки).
* Дерево не балансируется. Если вставлять слова строго по алфавиту, оно вырождается в список — для лабораторной это допустимо.

## Работа с git (по общим требованиям)

Один репозиторий на все лабораторные, папка `lab1`. Работа ведётся в feature-ветке, коммиты с понятными
сообщениями, в `main` — только через Pull Request. CI (`.github/workflows/ci.yml`) запускает тесты, проверку покрытия,
cppcheck и Doxygen, а при публикации тега (`git tag v1.0.0 && git push origin v1.0.0`) выкладывает архив
с Windows-программами в Releases.
